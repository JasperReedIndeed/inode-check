Two agent folders, one file

If two AI agents were set up as separate deployments, they can still end up on the same state file. The usual symptoms are a locked database, memories that bleed between agents, or one agent refusing to start because another holds it.

You can check it in one command. The check compares the metadata of two paths; it does not open anything.

python3 -B inode-check.py /srv/agent-a /srv/agent-b

Two paths that look different can be the same file: a hardlink, a symlink, or a parent folder that contains the other. The script compares device and inode numbers and the resolved path, then says which case you are in.

  • 0 — different file identities and no resolved nesting. Not a security pass.
  • 1 — same file, or one path resolves inside the other.
  • 2 — could not check. A failed check is not a clean result.

What it does not tell you

It does not compare contents, so two ordinary copies with identical bytes will pass as distinct — which they are, on disk. It does not read config, credentials, or conversation data, so it cannot tell you whether the two agents have the same settings. It does not test containers, network mounts or other filesystems, where identity rules differ.

This is a same-machine sanity check, not an isolation audit and not a security certificate. A live filesystem can change while you are looking at it.
